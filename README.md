# JULIUS WORKROOM v1.5.0

WORK SIMPLIFICATION + BODY REMOVAL / schema 12

「作業名を追加 → ▶で開始 → 記録する」だけで使えるWORKへ変更。
白と青のテーマ、EXERCISE、Google同期、JSONバックアップ、PWA、6種類の立ち絵は維持する。

## 今回の変更

- 大カテゴリとPROJECT階層を廃止。独立したWORK ITEMの横長カードを表示。
- 名前だけで追加。右の▶ですぐ開始。共通時間は5／15／25／45／60分。
- FOCUS TIMERに作業名、残り時間、一時停止／再開、記録・終了、取消。
- 完了は「記録する」だけ。メモは任意。CURRENT／NEXT／温度／負荷は廃止。
- 名前変更、アーカイブ、復元。IDで集計し、同名の別作業を勝手に統合しない。
- HOME／LOG／CALENDAR／統計も作業単位。INBOXは「作業にする」と「削除」。
- BODYのページ・入力・処理・専用台詞・同期集計を撤去。`bodyDays`も新データから除去。
- EXERCISEの6種、週間目標、回数型プランク、編集・削除、件数別台詞は維持。
- UI SEのQUIET 2.0／NORMAL 4.8、終了SE、端末別音設定は維持。

## 更新前に必ず行うこと

1. 公開中のv1.4.1で「JSONを書き出す」を押し、ファイルを別の場所へ保管する。
2. PCとiPhoneの同期完了を確認。未同期変更がある端末は、それぞれのJSONを保存する。
3. 更新中は旧版で入力しない。**両端末をv1.5.0へ再読み込みしてから**編集を再開する。

旧版と新版を同時に編集に使わない。旧版はschema 12の作業一覧を扱えない。
ブラウザのサイトデータやlocalStorageの削除は更新手順に含まれない。

## データ移行

保存キーは引き続き`julius_workroom_v1`。

- 全プロジェクトを`workItems`へ変換し、元のIDと名前を維持。
- `completedAt`→`archivedAt`。既存の作業日時を引き継ぐ。
- ログのID・日時・時間・メモを保持し、`projectId`→`workItemId`へ変換。
- 対応作業がない過去ログも保持し、必要な作業をARCHIVEに生成。
- 小さな一歩は`micro: true`、`workItemId: null`。ボタンのID・ラベルを保持。
- 動作中／一時停止中タイマーはIDと残り時間を引き継ぐ。参照先が移行元にも存在しない場合だけ取消す。
- EXERCISE、INBOX、同期テスト、週間目標、設定は保持。
- `categories`、CURRENT／NEXT／温度／負荷、`bodyDays`は新データから除去。

原本を端末内の別キー`julius_workroom_before_schema12`へ保存してから移行する。
別の旧JSONを後で読み込む場合は、前のコピーを接尾辞付きキーに残す。
設定の「更新前のJSONを保存」で直近の移行原本を書き出せる。
退避保存できない場合や形式不正時は初期化せず停止する。
端末内コピーもブラウザデータ削除には耐えないため、更新前JSONは外部ファイルでも保管する。

### JSONとロールバック

- 通常の書き出しはschema 12。`workItems`を含み、`categories`と`bodyDays`を含まない。
- v12の読み込みと、v11以前の旧データ変換に対応。
- 読み込み時は確認を出し、現在の記録をJSONへ書き出す。保存失敗時は元データを維持。
- 旧版へ戻す際は同期を止め、旧版アプリと**更新前v1.4.1 JSON**を組み合わせる。新版クラウドへの無確認の上書きはしない。

## Cloud Sync

同梱の`firebase-config.js`（Webアプリ用設定）を使用。サービスアカウント鍵は使わない。
保存先は変更せず`users/{uid}/workroom/state`。FirebaseのUID制限ルールやAuthentication設定は変更していない。

- ユーザー操作によるGoogleポップアップログインを維持。
- 初回比較、revision付きトランザクション、writerId、安全コピーを維持。
- v11のクラウド内容もv12へ正規化して比較。同内容なら毎回の選択は不要。
- 別端末更新と未同期変更が重なれば停止し、選択を待つ。
- 保存中に加わった変更も次の保存で送信。
- 容量表示と約900KB安全停止を維持。超過時もローカル記録とJSONは保持。
- 対応ブラウザでWeb永続キャッシュを有効化。最新世代を取得できないオフライン状態では送信しない。

## GitHub Pagesへの更新

ZIPは直下に`index.html`がある構成。

1. GitHub Desktopで`julius-workroom`を選び、「Repository → Show in Explorer」で管理フォルダを開く。
2. 更新前JSONを保存し、ZIPを別フォルダへ展開。
3. **ZIPそのものではなく中身**を既存`index.html`と同じ階層へコピーして上書き。
4. 新しい`schema.js`、`work-ui.js`と、`index.html`、`cloud-sync.js`、`service-worker.js`を必ず反映。6画像の名前は変更しない。
5. 変更一覧を確認しCommit、Push originを1回実行。
6. ActionsのPages公開成功を確認。エラー時はログを確認し、連続再実行しない。
7. PCとiPhoneで再読み込みし、v1.5.0表示を確認。iPhoneホーム画面アプリも閉じて開き直す。

既存のmain／root設定は変更しない。旧`body.svg`が残っても新版は参照しない。
`.git`やJSONバックアップは削除しない。

公開先: https://zeekkeezezek.github.io/julius-workroom/

## 公開後のPC → iPhone → PCテスト

両端末のJSONを保存してから行う。

1. 両端末をv1.5.0へ更新し、同じGoogleアカウントで「同期済み」を確認。
2. PCで「同期確認用」の作業を追加。iPhoneにもカードが現れることを確認。
3. iPhoneで5分を選び▶を押す。作業名とタイマーを確認。
4. 「記録・終了」→「記録する」。短いテストも1分以上として記録される。空メモで保存可能。
5. PCのLOGに記録が現れ、今日／累計時間も増えることを確認。
6. PCで名前変更とアーカイブ。iPhoneにも反映され、復元で通常一覧へ戻ることを確認。
7. 設定の「同期テストを追加」も各端末から1回ずつ押し、相手に表示されることを確認。
8. 両端末を再起動。同じデータで毎回比較画面が出ないことを確認。

競合時は双方のJSONを保存して残す側を選ぶ。テスト記録はLOGで削除でき、作業はARCHIVEへ保管できる。
本番Firestore・実機iPhoneでの往復同期は公開後に最終確認する。ローカル検証結果は`VERIFICATION_v1.5.0.md`を参照。
